# 多人模式：部署後 Smoke Test 清單

每次部署 Socket server（Cloud Run）或前端（Vercel）之後，用這份清單手動檢查主要流程。全部大約 10 分鐘，需要兩個瀏覽器或兩台裝置。

## 為什麼是手動清單，不是自動化

對正式環境跑自動化測試，會帶來以下風險：

| 風險 | 原因 |
|------|------|
| 打擾真實玩家 | 快速配對會把正在等待的真實玩家配進測試局 |
| 測試房間被看見 | 私人房間會出現在公開的房間列表，直到測試帳號離開 |
| 污染 GA4 | 正式網域會送 GA4 事件；自動化每次部署都跑，數據會被灌水 |
| 多一套基礎設施 | 還要維護正式環境專用的測試帳號、清理流程與排程 |

部署前的自動化驗證已經由 CI 和 E2E 涵蓋：
- 配對、再戰、斷線、電腦作答時限、資料隔離與分析事件的整合測試。
- Playwright E2E 涵蓋搶答雙人、重新整理、雙分頁、快速配對、再玩一場、封包檢查、分析事件。

正式環境只需要確認「部署後服務接得起來、主要流程正常」。手動操作十分鐘，比維護一套正式環境自動化可靠。

## 事前準備

- **GA4 已啟用「開發人員流量」排除篩選器**（見 `docs/MULTIPLAYER_ANALYTICS.md` 5.2）。
  - 所有測試網址都加 `?ga_debug=1`，測試事件就只會出現在 DebugView，不會進報表。
- **兩個瀏覽器（A、B）**：例如一般視窗加無痕視窗，或桌機加手機。暱稱用 `QA-A`、`QA-B`，方便辨認。
- **選流量低的時段**，減少把真實玩家配進測試局的機會。

## 清單

### 1. 連線與大廳

- [ ] 打開 `https://math24master.com/zh-TW/multiple-play?ga_debug=1`，大廳正常顯示，沒有一直停在「連線中」。
- [ ] DebugView 看得到 `multiplayer_lobby_view`。

### 2. 快速配對與電腦補位（A）

- [ ] A 按「快速開始」，進到房間頁，面板顯示：
  - 「正在尋找對手」
  - 「已有 1 位玩家（最多 4 人）」
  - 倒數秒數
- [ ] 按「取消配對」，回到大廳，「快速開始」按鈕可以再按（不會一直轉圈）。
- [ ] 再按一次「快速開始」，然後按「不等了，直接開始」：電腦補到 3 人並開局。
- [ ] 搶答一題，答對有加分。
- [ ] 重新整理頁面：回到同一局、分數不變；DebugView 沒有再出現一次 `game_start`。

### 3. 兩人配對（A、B）

- [ ] A、B 幾秒內先後按「快速開始」：兩人進到同一間房，人數顯示 2。
- [ ] 等倒數結束，或其中一人按「不等了」：兩邊看到相同的真人數與電腦數。
- [ ] 兩人同時按「搶答！」：只有一人拿到作答權，另一人看到已有人作答。

### 4. 結算與再玩一場（A）

- [ ] 打完一局（約 4 到 6 題），結算畫面顯示：
  - 勝利者（「你贏了！」或「某人獲勝」）
  - 自己的名次
  - 所有人的分數，電腦有「電腦」標記
- [ ] 按「再玩一場」：網址換成新的房間，面板回到「正在尋找對手」，分數從 0 開始。
- [ ] 按「取消配對」回到大廳。

### 5. 私人房間（A、B）

- [ ] A 按「開私人房間」，**設定密碼**（避免陌生人加入）；B 從網址加入並輸入密碼。
- [ ] B 按準備，A 開始遊戲，正常進行一局。
- [ ] 結束後 B 按「再玩一場」：回到房間並自動準備；A 可以直接開始下一局。
- [ ] A 按「回大廳」：B 成為房主，沒有出現「遊戲中斷」。
- [ ] B 也離開：房間從公開列表消失。

### 6. 收尾

- [ ] 兩個瀏覽器都回到大廳，房間列表裡沒有剩下 `QA-` 開頭玩家的房間。
- [ ] Cloud Run 的 log 沒有 `[socket] ... failed` 錯誤。
- [ ] 前端瀏覽器 console 沒有錯誤。

## 失敗時

| 症狀 | 先看哪裡 |
|------|----------|
| 一直停在「連線中」 | Vercel 的 `NEXT_PUBLIC_SOCKET_URL` 是否指向正確的 Cloud Run 網址；Cloud Run 的 `ALLOWED_ORIGINS` 是否包含正式網域 |
| 配對或開局卡住 | Cloud Run log；Cloud Run 是否仍是單一 instance（房間狀態在記憶體，多個 instance 會讓玩家分散） |
| 前端與伺服器行為對不上 | 兩邊是否部署同一個版本（照 Cloud Run 先、Vercel 後的順序） |
| DebugView 沒有事件 | 網址是否帶 `?ga_debug=1`；是否在正式網域（其他網域不會把事件送到 GA4）；是否開了廣告攔截 |

## 關於 Vercel preview

Preview 部署不會把事件送到 GA4，可以放心操作。但 preview 的前端通常連到正式的 Socket server，在 preview 建立的房間一樣會出現在正式環境。在 preview 測試私人房間時也請設定密碼，並在結束後離開。
