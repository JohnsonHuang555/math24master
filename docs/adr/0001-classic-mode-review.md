# ADR-0001：單人經典模式現況健檢（2026-08）

## 狀態

已確認共同理解。**這不是一份行動計畫**，是一次現況健檢的紀錄，作為之後規劃的參考基準。文中「後續可考慮方向」不是承諾要做的待辦。

## 背景（Context）

- 觸發原因：經典模式是目前全站流量最高的模式。
- 流量依據：已登入玩家的排行榜提交數，經典模式最多。**這個指標不含未登入訪客**，只反映「已登入且願意上傳分數」的子集，不是全站真實流量。
- 評估範圍：只評「單人經典模式」本身，不含每日挑戰／心算快答／挑戰模式（僅作對照）。
- 評估角度：玩家體驗、商業、技術三個角度綜合評估。
- 這份文件由 grilling 對話（domain-modeling）產生，過程中用 sub-agent 調查了程式碼現況，並由專案維護者（單人開發，本文件唯一讀者）逐項確認決策脈絡。

## 已確認的決策（Decisions）

這兩點是**刻意設計、非技術債**，未來不應被誤認為「沒做完」而重新展開：

### D1. 難度固定為 Hard，無難度選擇

- 現況：`Difficulty` enum 有 Easy（maxValue=6）/ Normal（maxValue=10）/ Hard（maxValue=13），但單人經典模式 UI（[app/single-play/[mode]/classic-play-game.tsx](../../app/single-play/[mode]/classic-play-game.tsx)）進場一律 `setDifficulty(Difficulty.Hard)`，玩家沒有機會選擇。
- 決策：只留一個難度是刻意選擇，Easy/Normal 在此模式的程式路徑上是死碼。
- 影響：`_maxValueFor()`（[lib/classic-single-play-engine.ts](../../lib/classic-single-play-engine.ts)）裡 Easy/Normal 分支目前無法被觸達，屬於可清理但不急的技術債，不是待補功能。

### D2. 手牌固定 4 張，不做「4 張 / 5 張牌數量」加分

- 背景：[TODOS.md#TODO-2](../../TODOS.md) 記錄「4 張牌 +1、5 張牌 +2」的加分規則曾在設計討論中提出，2026-04-08 工程審查後因與多人模式 `server/game.ts` 計分不一致而撤回。
- 決策：針對單人經典模式，此規則**正式定案關閉**——手牌本來就固定 4 張（沒有 5 張牌的情境），張數不構成計分維度。已同步關閉 [TODOS.md](../../TODOS.md) 的 TODO-2（僅限經典模式範圍；多人／拉密模式若未來調整手牌上限可另外評估，不受本次結論約束）。
- 已同步更新 [specs/scoring.spec.md](../../specs/scoring.spec.md)。

## 觀察到的落差與風險（尚未有結論，只是記錄）

以下四點不是決策，是這次健檢中發現、目前**沒有定案、也沒有數據**的灰色地帶：

### R1. 完美手加成 + S/A/B/C 解法評級，上線後零追蹤

- 經典模式獨有機制：用 `findAllSolutions()` 算出每手理論最高分，達標即「完美手」+1 分（`Player.perfectHands` / `Player.theoreticalMax`，見 [models/Player.ts](../../models/Player.ts)）；結算畫面另外顯示 S/A/B/C 解法評級（效率 = 實得分 / 理論最高分）。
- 風險：這套機制**上線後從未追蹤過任何數據或玩家回饋**，不知道它是否真的提升了滿足感，也不知道玩家看不看得懂/在不在乎這個評級。

### R2. 廣告與「截圖分享」的目標互相矛盾

- 2026-08-06 commit（`91788cf`）把經典模式結算畫面的 `AdUnit` 廣告位註解掉，理由是「怕結算畫面截圖分享時很醜」。
- 矛盾點：經典模式**目前完全沒有分享功能**（沒有分享按鈕、沒有像每日挑戰那樣的分享文字格式）。也就是已經為了一個還不存在的行為（玩家截圖分享）放棄了現成的廣告收益位。
- 這不是說廣告應該放回去，而是這個決策目前建立在一個尚未成立的假設上，值得記錄。

### R3. 核心痛點：單局回饋與長期進度都偏弱

- 即時回饋：答對當下只有 `+N分！`飄字文字 + 音效 + toast，沒有更強的視覺回饋。
- 結算成就感：結算畫面是純資訊卡片（分數／評級／效率），沒有慶祝感的呈現。
- 長期進度：經典模式沒有連勝統計、幾乎沒有專屬成就（14 個成就裡只有 `no_skip` 跟經典模式直接綁定），因此**沒有讓玩家想每天回來玩一局的誘因**。

### R4. 經典模式扛最大流量，但站內沒有承接長期參與的動線

- 專案裡已經有「每日挑戰」模式承擔「每天回訪」的產品定位（見 [specs/daily-challenge.spec.md](../../specs/daily-challenge.spec.md)）。
- 已確認的框架（非待辦，是這次對話的共識）：問題不是「經典模式要自己長出一個留存機制去跟每日挑戰模式重複」，而是「經典模式作為全站最大流量入口，跟其他模式／長期進度之間目前沒有任何連結」——玩完一局經典模式，不會被引導去做任何有累積感的事。

### R5. Genre-level 限制（附帶認知，非設計問題）

- 數學題材本身有天花板：不喜歡數學的玩家不會因為回饋做得更好而留下。這是這次討論明確標註的變數——後續任何「加強刺激感」的討論，都不該假設能靠 UI/UX 解決全部留存問題。

## 綜合評語

三個角度都看過一輪，結論是：**經典模式的核心規則本身是穩的（D1/D2 都是合理收斂），問題不在規則，在規則跑完之後「什麼都沒發生」。** 玩家答對、算完一局、拿到分數——然後呢？沒有任何東西把這一局跟「明天還想再來」或「跟其他模式產生關聯」串起來。R1（做了沒驗證效果的評級系統）跟 R3/R4（該有的回饋與承接完全空白）合起來看，比較像是「功能做了一半就停在展示層」——有一個評分系統，但沒有讓這個系統產生行為後果（不影響排行榜、不影響成就、沒人在追它有沒有用）。

R2 也是同一個症狀的另一個表現：因為要「顧及一個假設中的分享行為」而放棄現成收益，但那個分享行為本身沒有被實作出來——決策的因果鏈斷在半路。

這些都不是「這個模式做得不好」的評語，而是「這個模式的骨架是對的，但沒有被接上任何後續」。R5 的提醒也很重要：不是所有留存缺口都能靠加強回饋解決，值得在後續規劃時先想清楚要解決的是「回饋不夠」還是「沒有回訪理由」，這是兩個不同的問題，可能需要不同的答案。

## 後續可考慮方向（僅供規劃參考，非承諾）

- R1：至少加基本的事件追蹤（完美手觸發次數、玩家是否有回頭看評級），再決定要不要投資強化這個系統。
- R2/R3：若要做分享，得先想清楚分享的是「這一局的過程」還是「這一局的結果」，再決定結算畫面的視覺設計要不要保留給分享用途；否則現在拿掉廣告等於是白白損失收益。
- R4：思考「經典模式結束後」到「其他模式或長期進度」之間，有沒有一個輕量的橋接點（不需要重造一個每日機制）。
