# 訪客上榜要帶只存在裝置上的密鑰

訪客身分只是瀏覽器 localStorage 裡的一組 `guestId`，而排行榜的公開列表會回傳每一筆紀錄的 `userId`，訪客的 `userId` 就是 `guestId`。上傳成績時 server 只認送來的 `guestId`，所以任何人都能從排行榜複製別人的 `guestId`，自己玩一局拿到成績收據（見 ADR 0011），再用那個 `guestId` 上傳更高的分數，連暱稱一起蓋掉別人的紀錄。

考慮過不在公開列表回傳訪客的 `userId`，但前端靠它在榜上標出「我」，而且 `guestId` 本身就不是秘密，藏起來只是增加猜測難度。也考慮過讓訪客改用匿名登入（Firebase Anonymous Auth 之類），但要多一套登入流程。決定改成：

1. 訪客身分多一把密鑰 `guestKey`（uuid），只存在玩家的裝置上，從不公開。
2. 上傳成績時連同 `guestId` 一起送；server 在 `leaderboard_guests/{guestId}` 只存密鑰的 SHA-256 雜湊。
3. 這個 `guestId` 第一次出現時，用送來的密鑰登記；之後每次上傳都要相同的密鑰，不同就回 403。密鑰比對失敗時不會用掉成績收據。
4. 前端在有訪客身分、但還沒登記時，載入頁面就先呼叫 `POST /api/leaderboard/guest` 登記一次，不用等到下一次上榜。

## Consequences

- 已經在榜上的舊訪客沒有密鑰，升級後由「先登記的人」取得這個 `guestId`。本人通常下次開網站就會自動登記；如果在那之前被別人搶先登記，本人的前端會收到 403，改用新的 `guestId`（保留暱稱），舊紀錄留在別人手上。這是一次性的風險，之後就不會再發生。
- 密鑰跟 `guestId` 一樣只存在瀏覽器裡：清掉瀏覽資料或換裝置，訪客身分本來就會遺失，這點沒有變。
- Google 登入的玩家由 NextAuth 驗證身分，不需要密鑰。
