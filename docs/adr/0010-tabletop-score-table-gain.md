# 牌桌模式改為以桌面總分創新高的部分計分，並只保留一種難度

測試期（2026/10/24～11/07）結束後檢查排行榜：困難最高 147 分、最低 1 分，落差很大。資料裡沒有偽造的跡象（遠低於上限 2590），落差來自計分規則：回合得分是「完成的那一組的整組分數」，所以拆開桌上的高分組（最高 30 分）、換進 1 張手牌重組，就能再拿一次整組分數。最好的策略因此變成每回合只出 1 張、把手牌留著拖長對局，跟正常出牌的玩家差好幾倍。

決定改成：**回合得分 = 新桌面總分超過本局桌面最高紀錄的部分，每打出 1 張手牌至少 1 分**。桌面總分是桌上每一組分數的總和；最高紀錄只升不降。

考慮過的替代方案：

- **新桌面總分 − 舊桌面總分，負的算 0**：可以用兩回合來回刷，先把桌面拆成低分組（只拿保底），下回合再重組回高分，又拿一次差額。以「最高紀錄」為準才擋得住。
- **允許負分**：數學上一樣擋得住，但玩家會看到「本回合 −20」，保底也難定義。
- **只算完成的那一組減掉它吸收的原牌組分數**：比較接近原本「只有完成的那一組計分」的定義，但牌被分散到多組時很難定義「原牌組」，也很難跟玩家解釋。

同時移除簡單、普通難度，只保留原本的困難：玩家幾乎都直接選困難，三個難度只會分散排行榜。

## Consequences

- CONTEXT.md「完成牌組」不再是計分單位：重排其他牌組讓桌面總分創新高，也算進這回合的得分。
- Bot 改用同一個 `scoreTurn` 評估候選走法；Bot 拆組讓桌面總分下降之後，下一個把桌面重建回原本分數的人只拿保底。Bot 會挑對自己最有利的走法，很少主動降低桌面總分，影響不大。
- 單局得分不超過「桌面最高總分 + 保底 + 出完加分」：106 張最多約 21 組 × 30 分 ≈ 640，加上保底最多 86、出完加分 10，排行榜上限從 2590 改成 750。
- 排行榜 mode 沿用 `tabletop_hard`（collection `leaderboard_tabletop_hard`），不必搬資料；`tabletop_easy`、`tabletop_normal` 不再接受。新規則上線時清空 `leaderboard_tabletop_hard`，刪除另外兩個 collection；瀏覽器裡的個人最佳也重置（stats-store v6）。
- 測試期提示（`lib/tabletop-beta.ts`）與 Beta 標示一起移除。
- API 仍然相信前端送來的分數，上限只能擋明顯造假的成績；伺服器重播驗證另開 issue 處理（#117）。
