搶答模式（Buzzer Mode）實作計劃

Math24Master — 新多人遊戲模式，完整規格 + 分階段實作

核心規則摘要

項目說明
公共牌系統隨機產生可解的 4 張牌，顯示在畫面中央
搶答流程發牌 → 3 秒等待 → 開放搶答 → 搶到者有 N 秒作答
作答成功依原本計分規則加分 + Streak 獎勵
作答失敗/超時扣分 + 鎖定 N 秒（可設定）
無解投票多數決（母數=全部玩家），通過後跳回合不扣分
回合計時搶答成功時暫停；作答結束後 1-2 秒緩衝後恢復
換回合解鎖可設定（開/關），新回合開始是否自動解除鎖定
Streak失敗/超時重置；不搶答不中斷；公開顯示給所有人
勝利條件立即結束；同分看達標時間戳記
玩家人數2–6 人（含 AI Bot）
斷線處理算超時 → 扣分 + 鎖定

房間設定項目（BuzzerSettings）

欄位說明選項（預設）
presetMode預設模式，選後自動填充其他設定'standard' | 'fast' | 'casual' | 'custom'（standard）
answerSeconds搶答成功後的作答秒數10 | 15 | 20 | 25 | 30（15）
penaltyPoints作答失敗/超時扣分0 | 1 | 2 | 3（2）
lockSeconds作答失敗/超時鎖定秒數10 | 15 | 20 | 25 | 30（15）
winScore達標勝利分數15 | 20 | 25 | 30（20）
roundSeconds每回合總時間（null=不限時）null | 30 | 60 | 90（60）
roundTimeoutPenalty回合計時結束無人答對的扣分（roundSeconds=null 時 disabled）0 | 1 | 2 | 3（1）
scoreFloor分數下限（null=不設定）null | 0 | -5 | -10（null）
streakBonus連勝額外加分方式'none' | 'n1' | 'n2'（n2）
cardMaxValue牌面最大值10 | 13（13）
clearLockOnNewRound新回合開始是否自動解除鎖定true | false（true）

分階段實作

1
Models & Types
models 基礎定義
models/Room.ts 修改
  • GameType 加入 'buzzer'
  • 新增 BuzzerSettings 型別（含 11 個設定項目）
  • 新增 BuzzerState 型別（publicCards, roundTimerElapsed, currentAnswerPlayerId, noSolutionVotes, playerStates map）
  • RoomSettings 加入 buzzerSettings?: BuzzerSettings
  • Room 加入 buzzerState?: BuzzerState
models/SocketEvent.ts 修改
  • 加入上表 16 個新 BuzzerXxx 事件
2
Server — 核心遊戲邏輯
server buzzer.ts 新檔
server/buzzer.ts 新增
  • generateSolvableCards(maxValue) — 產生可解 4 張牌（複用 canMake24 solver）
  • startBuzzerRound(room) — 初始化 BuzzerState、清空投票、依設定決定是否清除鎖定
  • processBuzzIn(room, playerId, serverTimestamp) — 先到先得；回傳搶答成功/失敗
  • processBuzzerAnswer(room, playerId, equation) — 驗算（mathjs）；成功→計分+streak；失敗→扣分+鎖定；檢查勝利條件
  • processNoSolutionVote(room, playerId) — 累加投票；過半數→回傳 passed=true
  • applyRoundTimeout(room) — 全員扣 roundTimeoutPenalty 分（除非設定為 0）；套用 scoreFloor
  • calculateBuzzerScore(equation, streak, streakBonus) — 原本計分規則 + streak 加分
  • applyScoreFloor(score, floor) — 套用分數下限
lib/math24-solver.ts 新增（或確認現有）
  • 從 lib/daily-seed.ts 提取 canMake24 solver 為獨立模組（讓 server 可直接 import）
  • 若已存在可跳過此步驟
3
Server — Timer 管理
server index.ts 擴充
server/index.ts 修改
  • 新增 buzzerRoundTimerMap：記錄每個 room 的回合 timer（含 paused state、elapsed、remaining）
  • 新增 buzzerAnswerTimerMap：記錄當前作答玩家的 15 秒 timer
  • 新增 buzzerLockTimerMap：記錄每個玩家的鎖定 timer（Map<playerId, Timeout>）
  • _startBuzzerRound(roomId)：開始新回合 → emit BuzzerCountdown 3/2/1 → emit BuzzerOpen → 啟動回合 timer
  • _pauseBuzzerRoundTimer(roomId)：停止 interval、記錄 elapsed
  • _resumeBuzzerRoundTimer(roomId)：從 elapsed 恢復倒數
  • _startAnswerTimer(roomId, playerId)：15 秒後若未作答觸發超時
  • _lockPlayer(roomId, playerId)：emit BuzzerPlayerLocked，設定 timer 到期後 emit BuzzerPlayerUnlocked
  • _handleAnswerEnd(roomId, isCorrect)：1-2 秒 buffer 後恢復回合 timer
4
Server — Socket Event Handlers
server index.ts Socket 處理
server/index.ts 修改（續）
  • on(BuzzerBuzzIn)：呼叫 processBuzzIn；成功→pause timer + emit BuzzerBuzzInSuccess；失敗→emit BuzzerBuzzInFailed（僅對本人）
  • on(BuzzerSubmitAnswer)：呼叫 processBuzzerAnswer；成功→emit BuzzerAnswerResult + 檢查 GameOver；失敗→lock + emit BuzzerPlayerLocked；兩者都要 _handleAnswerEnd
  • on(BuzzerVoteNoSolution)：呼叫 processNoSolutionVote；passed→emit BuzzerNoSolutionPassed → _startBuzzerRound
  • StartGame handler：若 gameType==='buzzer' 改走 _startBuzzerRound
5
Client — 房間設定 UI
client 建立房間 Modal
components/modals/create-room-modal.tsx 修改

  • 頂部加入預設模式下拉（標準/快節奏/休閒）→ 自動填充各設定值

Client — 遊戲畫面 UI
client 新 UI 元件
components/areas/buzzer/ 新增資料夾
  • buzzer-game-board.tsx — 整體版面容器（公共牌區 + 玩家列表 + 計時器 + 搶答按鈕）

8
AI Bot
bot server 端模擬
server/buzzer-bot.ts 新增
  • triggerBuzzerBot(room, io) — 每回合開牌後由 server 呼叫，模擬 bot 行為
  • Bot 先用 canMake24 確認是否有解；有解才會嘗試搶答
  • 根據難度決定「思考時間」後呼叫 processBuzzIn（同真實玩家流程）
  • 搶到後模擬「輸入時間」，再呼叫 processBuzzerAnswer 提交正確算式
難度搶答延遲正確率
easy4–8 秒（隨機）60%（有時故意答錯）
normal2–5 秒85%
hard0.8–2 秒98%
Bot 難度選項沿用現有 botDifficulty: 'easy' | 'normal' | 'hard'，AddBotToRoom 事件不需改動。

實作順序建議

順序Phase理由
1Phase 1（Models）型別定義是所有後續步驟的基礎
2Phase 2（server/buzzer.ts）純函數，可獨立測試邏輯
3Phase 3+4（Server Timer + Socket）一起做，timer 和 event 高度耦合
4Phase 5（房間設定 UI）讓前端可以創建 buzzer 房間
5Phase 6（Provider）Client 狀態層，UI 的基礎
6Phase 7（遊戲 UI）最後實作，依賴所有前面步驟
7Phase 8（AI Bot）最後補上，不影響主要遊戲流程
